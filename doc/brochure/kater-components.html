Weak memory model toolkit · GPLv3

Kater

Proves facts about weak memory models, and generates the consistency checkers that the GenMC model checker runs.

What it does

Metatheory

A model is written as relations over execution graphs (po, rf, mo, fr, …) built with sequence, union, intersection and closure. Kater turns each assert into a question about automata and answers it: the inclusion holds, or here is a counterexample path.

Output: verdict per assertion, or a counterexample

GenMC export

With -e, the export statements of a model become C++ for GenMC: an acyclicity check, coherence, incremental views, and error and warning detectors. Kater first proves the side conditions its optimisations rely on.

Output: a ConsistencyChecker subclass for GenMC

Components

Six layers in src/

About 11,000 lines of C++23, built as six static libraries, one per layer, under a thin main.cpp. A layer may include headers only from itself and the layers below it; scripts/check-layers.sh enforces this and runs as a test. Each layer has a single contract it must meet.

Syntax

front end

Reads a .kat file into a KatModule: named relations, saved expressions, constraints and statements. Builtins declares the predefined relations and predicates (po, rf, [W], [ATOM], …).

kater_lang: Lexer.lpp · Parser.ypp · ParsingDriver · Builtins · KatModule · Assumptions · RegExp · Constraint · Statement · SavedExp

ContractThe parsed module means what the text says.

Theory

trusted

The structural facts Kater may assume about execution graphs: domains and codomains of relations, per-location variants, and which predicates include or exclude one another. Hypotheses stated as formulae, the built-in ones and the user's assume lines such as assume rf ; [F] = 0, live in Assumptions next to the module; the ones that are plain facts are folded into the theory.

kater_theory: Theory · Predicate · Relation · TransLabel

ContractEvery hypothesis is true of all executions of the model.

Automata

trusted

Nondeterministic automata whose edges are relations and predicate tests. Provides reachability, state merging (findSimilarStates), edge joining, minimisation, and counterexample paths.

kater_automata: NFA · NFAUtils · StatePair · Counterexample · Utils

ContractEach operation keeps, or computes, exactly the stated language.

Decision procedure

trusted

Saturates the right-hand automaton with the module's assumptions, then checks whether the left-hand DFA's language is contained in it. Checker holds the rewrites (normalize, reduce, pruneNFA, expandRfs), realises each assumption as a saturation step, and runs assertions in parallel when TBB is present. It is configured by a two-field CheckerOptions, not by the command line.

kater_decision: Checker · Saturation

ContractA "holds" verdict means the inclusion holds under the theory.

Export

generated code

Rewrites the module for speed and prints a GenMC checker: incremental views, the ppo/rf prefix, coherence, and the error and warning detectors. Before optimising it asks the decision procedure to prove its side conditions, for example isPPOIntersectionInPPO.

kater_export: Exporter · GenMCPrinter · Printer · CodeBuilder

ContractThe checker accepts exactly the consistent executions.

Support

infrastructure

Command-line configuration, error reporting with source locations, a thread-safe logger with -v levels and debug types, and small containers used throughout.

kater_support: Config · Error · DbgInfo · Logger · AdjList · VSet · Visitor

ContractNo crashes and no undefined behaviour.

Using it

Build and run

cmake -DCMAKE_BUILD_TYPE=Release -B Release -S .
cmake --build Release -j$(nproc)

./Release/kater tests/correct/equivalence/eq-eco.kat
./Release/kater -e -n sc -p out/ kat/sc-genmc.kat

Needs a C++23 compiler, CMake, flex and bison. TBB is optional and enables parallel assertion checking.

Tests

tests/correct and tests/wrong hold models that must pass or fail, grouped as basic, compilation, equivalence, parsing and soundness. tests/unit covers the NFA and regular-expression code.

cd scripts && ./checkall.sh
./scripts/lint.sh

check-drivers.sh exports checkers from kat/ and builds them against a GenMC checkout.

Checking Kater · tests/oracle

A reference semantics to test against

kater-oracle gives .kat its meaning on GenMC's execution graphs and asks Z3 for a small graph that refutes what Kater claims. It shares Kater's parser and nothing of its inference, so a counterexample to a proved assertion is a soundness bug.

CommandWhat it checks
checkEach assertion's verdict against a counterexample search
auditEvery fact the Theory states about the builtins, against GenMC's meaning
transformsEach automaton pass of the decision procedure against its contract
exportThe claims an export relies on, and that its rewrites keep their meaning
fuzz.pyRandom assertions and assumptions, Kater against the oracle

It found six ways in which Kater proved false claims, and four crashes or code-generation errors, all fixed with regression tests; among them ctrl <= po-loc in the theory, compilation schemes saturated as an empty set, and words dropped by the & id passes. doc/verification.md has the model, the contracts and the findings; ctest -L oracle runs the checks.
